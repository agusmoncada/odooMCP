╔══════════════════════════════════════════════════════════════════════════════╗
║              DISCUSS MODULE INTEGRATION: COMPLEXITY ASSESSMENT                ║
╚══════════════════════════════════════════════════════════════════════════════╝

Integration Type            │ Effort  │ Complexity │ Recommendation
────────────────────────────┼─────────┼────────────┼────────────────────────────
Full Discuss Integration    │ 10-15w  │ Very High  │ NOT RECOMMENDED
  • Uses mail.message       │         │            │ Significant refactoring
  • Document threading      │         │            │ Changes to all layers
  • Email integration       │         │            │ Complex migrations
────────────────────────────┼─────────┼────────────┼────────────────────────────
Hybrid Approach (BEST)      │ 2-3w    │ Low-Med    │ RECOMMENDED ✓
  • Keep current widget     │         │            │ Minimal disruption
  • Add document linking    │         │            │ Leverages existing code
  • Optional context pass   │         │            │ Low risk
────────────────────────────┼─────────┼────────────┼────────────────────────────
AI-Specific Channel         │ 3-4w    │ Medium     │ ALTERNATIVE
  • Create dedicated channel│         │            │ Good for team sharing
  • Sync to mail.message    │         │            │ Email notifications
  • Keep sessions separate  │         │            │ More work than hybrid
────────────────────────────┼─────────┼────────────┼────────────────────────────
Context-Only Integration    │ 1-2w    │ Low        │ QUICK WIN
  • Document context in AI  │         │            │ No data model changes
  • No storage to mail      │         │            │ System prompt injection
  • Read-only integration   │         │            │ Simplest option
────────────────────────────┼─────────┼────────────┼────────────────────────────

KEY INSIGHT: The current architecture is OPTIMIZED for standalone AI assistant
role. Discuss integration would require abandoning custom data models for the
mail.message protocol, which has different fields & semantics. 

RECOMMENDATION: Use hybrid approach = best value with minimal effort.

┌─ #1 DATA MODEL (HIGH IMPACT) ─────────────────────────────────────────────────┐
│ Current:   ai.chat.message {role, content, tool_calls, metadata}             │
│ Discuss:   mail.message {author_id, model, res_id, body, subject, ...}      │
│ Problem:   Incompatible schema; tool_calls don't fit mail model               │
│ Impact:    Need migration strategy + custom extensions                        │
│                                                                                │
└────────────────────────────────────────────────────────────────────────────────┘

┌─ #2 THREADING (HIGH IMPACT) ──────────────────────────────────────────────────┐
│ Current:   Flat sessions (Session → Messages)                                │
│ Discuss:   Document-threaded (Document → mail.thread → messages)             │
│ Problem:   AI sessions not tied to documents; threading model differs         │
│ Impact:    Add res_model/res_id; decide per-document vs global               │
│                                                                                │
└────────────────────────────────────────────────────────────────────────────────┘

┌─ #3 UI COMPONENT (HIGH IMPACT) ───────────────────────────────────────────────┐
│ Current:   Modal dialog with session sidebar                                  │
│ Discuss:   Embedded in document chatter; no sidebar                           │
│ Problem:   Completely different layout paradigm                               │
│ Impact:    Rewrite widget template; embed in chatter context                 │
│                                                                                │
└────────────────────────────────────────────────────────────────────────────────┘

┌─ #4 REAL-TIME (MEDIUM IMPACT) ────────────────────────────────────────────────┐
│ Current:   Polling-based service; manual RPC calls                            │
│ Discuss:   Bus-based real-time; WebSocket notifications                       │
│ Problem:   No live multi-user updates; sync issues                            │
│ Impact:    Integrate with Odoo bus service for real-time                     │
│                                                                                │
└────────────────────────────────────────────────────────────────────────────────┘

┌─ #5 ACCESS CONTROL (MEDIUM IMPACT) ───────────────────────────────────────────┐
│ Current:   User-scoped only (Session.user_id = current)                      │
│ Discuss:   Follower-based (mail.followers ACL)                               │
│ Problem:   No multi-user sharing; no follower notifications                   │
│ Impact:    Implement mail.followers; notification system                      │
│                                                                                │
└────────────────────────────────────────────────────────────────────────────────┘

┌─ #6 EMAIL (MEDIUM IMPACT) ────────────────────────────────────────────────────┐
│ Current:   No email; PDF-only processing                                      │
│ Discuss:   Full SMTP/IMAP integration; incoming threads                      │
│ Problem:   No email notifications or incoming mail handling                   │
│ Impact:    SMTP sender setup; catchall email routing                          │
│                                                                                │
└────────────────────────────────────────────────────────────────────────────────┘
